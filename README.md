# n8n GitHub Actions 第一阶段验证

这个仓库只验证一件事：

> GitHub Actions 能否临时启动 n8n、安装原工作流需要的节点，并成功导入 `n8n信息聚合器`。

## 本阶段没有做什么

- 不连接 Cloudflare R2。
- 不新增网页发布。
- 不启用每天 8 点的定时任务。
- 不修改原 n8n 工作流的节点和连接。
- 不保存 n8n 数据库，任务结束后临时环境全部销毁。

原工作流末尾已有飞书节点，所以默认只导入、不执行，避免第一次测试就产生外部推送。

## 自动验证

修改 `.phase1/run-request` 会触发一次验证。验证会：

1. 下载固定版本 `n8n@2.47.4`。
2. 启动一个临时 n8n。
3. 安装飞书社区节点 `@songlipeng2003/n8n-nodes-feishu-lite@0.4.7`。
4. 导入压缩保存的原工作流。
5. 导出并核对工作流 ID、名称和节点数量。
6. 显示日志并删除临时容器。

原工作流在仓库中按 gzip + Base64 保存，运行时会还原为原始 JSON。其原始 SHA-256 是：

```text
492A6C99A7AF6AC71D8AD45017DB4FF1D907881672D323DC7D521B17BB4F28EF
```

## 执行整条工作流

只有完成下面两项后，才从 Actions 页面手动运行并勾选 `execute_workflow`：

1. 在 GitHub 仓库的 **Settings → Secrets and variables → Actions** 中添加 `N8N_CREDENTIALS_JSON`。
2. 确认你已经准备好原工作流需要的凭据。

`N8N_CREDENTIALS_JSON` 应是一个 JSON 数组，格式见 `n8n/credentials.example.json`。必须保留原工作流引用的凭据 ID，否则节点无法关联凭据。

不要把任何密钥提交到本仓库，也不要发到聊天中。

## 当前限制

- 每次运行都是全新的临时 n8n，没有编辑器数据、执行历史或持久数据库。
- 如果原工作流依赖的节点版本或凭据格式不兼容，导入会成功，但执行可能失败。
- 执行整条工作流会运行原有飞书节点。本阶段不会替原工作流屏蔽外部推送。
